# Decal benchmarks

참고: C:/Users/JUNGLE/Documents/decalTest.scene. 원본 파일과 엔진 코드는 변경하지 않았습니다.
두 씬은 참고 씬의 Cube, hitori.png 데칼 재질, 방향광/환경광을 사용합니다.

## 공통 측정 조건

- 에디터에서 씬을 열고 카메라 Location=(-32, 0, 0), Rotation=(Pitch=0, Yaw=0, Roll=0), FOV=70 정도로 설정합니다. +X 방향을 바라보며 중앙의 패널 전체가 보이도록 합니다. 카메라 위치는 씬에 자동 저장된 것으로 가정하지 않습니다.
- 같은 뷰포트 크기(권장 1920x1080), 카메라, 조명, 렌더 옵션을 유지하며 Settings의 Decal Method만 전환합니다.
- Depth 방식은 Decal Receiver Stencil을 켠 상태로 비교합니다. 수신 프레임도 bReceiveDecal=true이므로 Mesh용 씬의 부하를 단순히 스텐실로 모두 제거하지 못하게 했습니다.
- stat decal, stat fps를 켜고 로드/셰이더 준비 후 10초 이상 기다린 다음 각 방식을 10초 이상 관찰합니다. 선택 외곽선, 데칼 볼륨 표시, 와이어프레임은 끕니다. 가능하면 VSync/프레임 제한을 해제하고 에디터 실행 상태를 동일하게 유지합니다.
- FPS뿐 아니라 Decal CPU의 Receiver Selection/Submit과 Decal GPU ms, Draw Calls, Submitted Triangles를 비교합니다. Far Fallback은 0인지 확인합니다.
- 두 씬의 FPS 자체를 서로 비교하지 않고, 각 씬 안에서 두 방식의 시간을 비교합니다.

## DecalBenchmark_Mesh.scene

수신 Cube 1개(0.5 x 8 x 16), 앞쪽 프레임 Cube 4개, 동일 위치의 Lit 데칼 512개(4 x 40 x 24).

중앙 수신 패널은 X=0, 프레임은 X=-4, 데칼 깊이는 X=-2..2입니다. 따라서 프레임은 화면에 보이고 receiver stencil은 기록하지만 데칼 볼륨에는 포함되지 않습니다. 프레임을 통과한 Depth 셰이더 작업은 월드 위치 복원 후 볼륨 밖으로 판정됩니다. 중앙 패널에서는 두 방식 모두 데칼이 보입니다.

Mesh 방식은 BVH로 프레임을 제외하고 중앙의 저폴리곤 패널만 512회 다시 그리는 구조입니다. Depth 방식은 더 넓은 화면 영역에서 깊이 읽기/좌표 복원을 반복합니다. 넓은 볼륨과 작은 실제 수신 표면의 차이를 강조한 의도적인 스트레스 씬입니다. 프레임을 데칼 깊이 안으로 옮기거나 bReceiveDecal=false로 바꾸면 비교 조건이 달라집니다.

예상: Mesh 쪽 GPU 시간이 유리. 중앙 패널의 512중첩으로 Mesh 방식에도 픽셀 부하가 있습니다. 실제 우열과 프레임 하락은 미측정입니다.

## DecalBenchmark_Depth.scene

32열 x 20행 = 수신 Cube 640개, Lit 데칼 128개(4 x 40 x 24).
Cube는 Y/Z 간격 1.15로 배치하고 X 위치에 작은 굴곡을 주었습니다. 데칼 128개 모두 640개 수신 메시와 겹치도록 했습니다.

Mesh 방식은 약 81,920 receiver-item 제출, Cube당 12삼각형이면 약 983,040삼각형을 데칼 패스에서 처리합니다. 이는 코드 구조에 따른 예상치이며 뷰 컬링 등에 따라 달라집니다. Depth 방식은 통상 128회 볼륨 제출/1,536삼각형으로 같은 표면에 투영합니다. 많은 수신 메시와 데칼의 조합으로 CPU 제출 및 지오메트리 비용 차이를 강조합니다. Depth 방식에도 128중첩 픽셀 부하가 있습니다.

예상: Depth 쪽 CPU 제출 및 지오메트리 비용이 유리. GPU/전체 프레임 시간은 실행 측정이 필요합니다.

## 부하 조정

프레임 하락을 보장하는 고정 개수는 장비별로 다릅니다. 너무 느리면 이름 끝 번호가 큰 데칼 절반을 삭제한 복사본으로 측정하고, 너무 빠르면 데칼들을 복제해 2배로 늘립니다. 두 방식 비교 시에는 동일한 씬과 데칼 개수를 유지합니다. 무데칼 기준값이 필요하면 복사본에서 UDecalComponent의 bDecalEnabled를 모두 끄고 측정합니다.

광원 그림자와 수신 메시의 그림자/충돌/오버랩 이벤트는 꺼서 데칼 이외 비용을 줄였습니다. 데칼의 NormalOpacity=0, 알파=0.025로 설정하여 중첩된 표면을 관찰하기 쉽게 했습니다. 실행 시 프레임과 중앙 패널이 구분되어 보이는지 확인하세요.
